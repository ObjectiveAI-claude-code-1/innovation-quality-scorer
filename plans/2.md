# Innovation Quality Scorer: Implementation Plan

## Overview

This plan defines the implementation of the `innovation-quality-scorer` function, a scalar function that evaluates the creative and innovative merit of startup ideas across multiple modalities (text, image, audio, video, or composite).

---

## 1. Input Schema Structure

```json
{
  "type": "object",
  "description": "Input for the innovation quality scorer. Accepts a startup idea in various formats.",
  "properties": {
    "idea": {
      "anyOf": [
        {
          "type": "string",
          "description": "A text-based startup pitch (elevator pitch, executive summary, one-liner, detailed description, etc.)"
        },
        {
          "type": "image",
          "description": "A visual startup pitch (pitch deck slide, napkin sketch, product mockup, concept diagram, etc.)"
        },
        {
          "type": "audio",
          "description": "An audio startup pitch (recorded elevator pitch, founder interview, verbal explanation, etc.)"
        },
        {
          "type": "video",
          "description": "A video startup pitch (demo video, pitch recording, prototype demonstration, vision film, etc.)"
        },
        {
          "type": "array",
          "description": "A composite startup pitch combining multiple elements (pitch deck with text, images, and embedded videos)",
          "items": {
            "anyOf": [
              {"type": "string"},
              {"type": "image"},
              {"type": "audio"},
              {"type": "video"}
            ]
          }
        }
      ]
    }
  },
  "required": ["idea"]
}
```

### Field Descriptions

| Field | Type | Description |
|-------|------|-------------|
| `idea` | anyOf | The startup idea to evaluate. Can be text, image, audio, video, or an array combining multiple formats. |

### Input Modality Examples

- **String**: "We're building a marketplace that connects elderly people with teenagers for mutual mentorship and companionship, where both parties pay a small fee that funds community centers."
- **Image**: A pitch deck slide, whiteboard sketch, or product mockup
- **Audio**: A 60-second recorded elevator pitch
- **Video**: A 3-minute demo video or pitch recording
- **Array**: A full pitch deck with text, images, and embedded demo video

---

## 2. Input Maps

**No input maps are needed.** This function evaluates a single startup idea, not a collection. The input structure is straightforward with a single `idea` field that accepts multimodal content.

---

## 3. Function Definition Structure

```json
{
  "type": "scalar.function",
  "description": "Evaluates the creative and innovative merit of a startup idea. Returns a score from 0 (completely derivative) to 1 (genuinely groundbreaking). Assesses conceptual novelty, technical/business model innovation, insight depth, cliché avoidance, and first-principles thinking. Accepts text, image, audio, video, or composite pitches.",
  "input_schema": { /* as defined above */ },
  "tasks": [
    /* 14 vector.completion tasks as defined below */
  ]
}
```

## 4. Task Definitions

The function comprises 14 evaluation tasks organized into 5 conceptual categories. Each task uses `vector.completion` with binary (LOW/HIGH) or 5-level response options.

### Category 1: Conceptual Novelty (Tasks 1-2)

#### Task 1: Core Concept Novelty
- **Type**: `vector.completion` with binary responses
- **System prompt**: Expert startup evaluator assessing whether the idea introduces genuinely new concepts
- **Responses**: LOW (derivative/copy) vs HIGH (genuinely new paradigm)
- **Output expression**: `output['scores'][1]` (probability of HIGH)

#### Task 2: Problem Reframing
- **Type**: `vector.completion` with binary responses
- **System prompt**: Expert evaluator assessing whether the idea reframes the problem in a fundamentally new way
- **Responses**: LOW (accepts conventional framing) vs HIGH (fundamentally reframes)
- **Output expression**: `output['scores'][1]`

### Category 2: Technical/Business Model Innovation (Tasks 3-4)

#### Task 3: Technical Innovation
- **Type**: `vector.completion` with binary responses
- **System prompt**: Expert evaluator assessing technical novelty and breakthrough applications
- **Responses**: LOW (commodity tech) vs HIGH (genuine technical breakthrough)
- **Output expression**: `output['scores'][1]`

#### Task 4: Business Model Innovation
- **Type**: `vector.completion` with binary responses
- **System prompt**: Expert evaluator assessing novel value creation/capture mechanisms
- **Responses**: LOW (conventional model) vs HIGH (genuinely new model)
- **Output expression**: `output['scores'][1]`

### Category 3: Insight Depth (Tasks 5-6)

#### Task 5: Domain Insight Depth
- **Type**: `vector.completion` with 5-level responses
- **System prompt**: Expert evaluator assessing depth of domain understanding
- **Responses**: None / Shallow / Moderate / Deep / Profound
- **Output expression**: Weighted sum `output['scores'][0]*0.0 + output['scores'][1]*0.25 + output['scores'][2]*0.5 + output['scores'][3]*0.75 + output['scores'][4]*1.0`

#### Task 6: Contrarian Knowledge
- **Type**: `vector.completion` with binary responses
- **System prompt**: Expert evaluator assessing whether the idea is built on contrarian but substantiated knowledge
- **Responses**: LOW (follows conventional wisdom) vs HIGH (substantiated contrarian insight)
- **Output expression**: `output['scores'][1]`

### Category 4: Cliché Avoidance (Tasks 7-9)

#### Task 7: Structural Cliché Avoidance
- **Type**: `vector.completion` with binary responses
- **System prompt**: Expert evaluator detecting "Uber for X" and "A meets B" patterns
- **Responses**: LOW (relies on structural clichés) vs HIGH (articulates value in own terms)
- **Output expression**: `output['scores'][1]`

#### Task 8: Buzzword Independence
- **Type**: `vector.completion` with binary responses
- **System prompt**: Expert evaluator detecting buzzword reliance vs specific capability description
- **Responses**: LOW (buzzword-dependent) vs HIGH (specific and substantiated)
- **Output expression**: `output['scores'][1]`

#### Task 9: Market Claim Authenticity
- **Type**: `vector.completion` with binary responses
- **System prompt**: Expert evaluator detecting lazy market claims vs genuine insight
- **Responses**: LOW (generic claims) vs HIGH (specific, defensible insights)
- **Output expression**: `output['scores'][1]`

### Category 5: First-Principles Thinking (Tasks 10-12)

#### Task 10: First-Principles Evidence
- **Type**: `vector.completion` with binary responses
- **System prompt**: Expert evaluator detecting reasoning from fundamentals
- **Responses**: LOW (builds on unexamined assumptions) vs HIGH (reasons from first principles)
- **Output expression**: `output['scores'][1]`

#### Task 11: Assumption Identification
- **Type**: `vector.completion` with binary responses
- **System prompt**: Expert evaluator detecting explicit identification and challenging of assumptions
- **Responses**: LOW (accepts assumptions implicitly) vs HIGH (explicitly challenges assumptions)
- **Output expression**: `output['scores'][1]`

#### Task 12: Solution Inevitability
- **Type**: `vector.completion` with binary responses
- **System prompt**: Expert evaluator assessing whether solution feels derived vs arbitrary
- **Responses**: LOW (arbitrary choice) vs HIGH (inevitable from deep understanding)
- **Output expression**: `output['scores'][1]`

### Category 6: Holistic Assessment (Tasks 13-14)

#### Task 13: Paradigm Shift Potential
- **Type**: `vector.completion` with binary responses
- **System prompt**: Expert evaluator assessing transformational potential
- **Responses**: LOW (incremental improvement) vs HIGH (potential paradigm shift)
- **Output expression**: `output['scores'][1]`

#### Task 14: Overall Innovation Impression
- **Type**: `vector.completion` with 5-level responses
- **System prompt**: Expert evaluator providing holistic innovation assessment
- **Responses**: Derivative / Incremental / Solid / Innovative / Exceptional
- **Output expression**: Weighted sum `output['scores'][0]*0.0 + output['scores'][1]*0.25 + output['scores'][2]*0.5 + output['scores'][3]*0.75 + output['scores'][4]*1.0`

## 5. Expression Patterns

### Input Reference Pattern
All tasks reference the input idea using JMESPath:
```json
{"$jmespath": "input.idea"}
```

### Binary Response Output Pattern
For tasks with 2 responses (LOW/HIGH):
```json
{"$starlark": "output['scores'][1]"}
```
This returns the probability of the HIGH response.

### 5-Level Response Output Pattern
For tasks with 5-level responses:
```json
{"$starlark": "output['scores'][0] * 0.0 + output['scores'][1] * 0.25 + output['scores'][2] * 0.5 + output['scores'][3] * 0.75 + output['scores'][4] * 1.0"}
```
This computes a weighted average mapping to [0, 1].

### User Message Pattern
Simple direct reference to the idea:
```json
{
  "role": "user",
  "content": {"$jmespath": "input.idea"}
}
```

Or with prefixed instruction text:
```json
{
  "role": "user",
  "content": [
    {"type": "text", "text": "Evaluate the following startup idea:"},
    {"type": "text", "text": {"$jmespath": "input.idea"}}
  ]
}
```

## 7. Implementation Notes

### Task Independence
All 14 tasks are independent and can execute in parallel. There are no dependencies between tasks.

### Score Aggregation
The final score is the average of all task outputs. Each task produces a value in [0, 1], and the mean produces the final innovation quality score.

### Multimodal Handling
The system prompt for each task should instruct the evaluator to assess the underlying idea regardless of presentation format. Specifically:
- Do NOT reward polished presentations
- Do NOT penalize rough sketches or informal pitches
- Focus on the substance of the idea, not the production quality

### Edge Cases
- **Empty or minimal input**: Should score very low (no content to evaluate)
- **Pure marketing copy**: Should score low (clichés, no substance)
- **Technical jargon**: Should be evaluated on actual innovation, not impressiveness of language
- **Non-English input**: Should still be evaluated on the idea's merits

### Calibration Guidance
Include in system prompts:
- 0.0-0.2: Derivative (copies, obvious combinations)
- 0.2-0.4: Incremental (modest improvements)
- 0.4-0.6: Solid (genuine thought, some novelty)
- 0.6-0.8: Innovative (genuinely new approaches)
- 0.8-1.0: Exceptional (potential paradigm shifts)

Remind evaluators that truly exceptional ideas (0.8+) should be rare.
